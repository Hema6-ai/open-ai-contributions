# Level 6 - Meaningful Feature Implementation

## Goal
Design and implement a feature that didn't exist before: new API, new
sampling method, new connector/backend, new config surface, within an
existing architecture.

## Bar for done
- You can state the design: what the feature does, what it doesn't do, and
  why you chose this shape over alternatives you considered.
- You've checked how it interacts with existing features (not built in
  isolation from the rest of the system).
- Tests cover the new behavior, including interaction with existing
  behavior.
- Docs for the feature exist and match what the code actually does.
- Maintainers' review feedback (if any) is tracked here: what they pushed
  back on and why.

## Why this matters
This is the first level that requires genuine design judgment, not just
careful reading. Mistakes here are usually about scope or about not
understanding how the feature fits the broader architecture.
